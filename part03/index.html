00제3부 실습 개요

00~12장에서는 MAC·DSP·BRAM·4PE·UART 기반 소형 4분류 NPU를 이해합니다. 13~19장에서는 8×8·28×28 입력의 10분류 정수 MLP, 20~27장에서는 AXI4-Lite·MicroBlaze V SoC 통합, 28~31장에서는 숫자 인식·센서 융합·모터 제어·보안 UART로 확장합니다. 4분류와 10분류는 별도 하드웨어 구성입니다.

014개 누적 프로젝트 · 실습 및 보드 확인 경로

제3부는 32개의 독립 프로젝트가 아닙니다. 준비 00장과 정규 01~31장은 기존 소스·검증 결과를 유지하고 기능을 추가하는 네 단계입니다. 13~31장의 신규 RTL·SoC는 실제 코드와 검증 절차를 연결해 순차적으로 제작합니다.

체계화 · 이전 모듈 → 신규 모듈 → 검증 → 다음 장 인계
순서화 · RTL TB → Python 비교 → 합성/타이밍 → Bitstream → 보드
구조화 · 공통 NPU Core / UART / AXI / CPU / 응용 Controller 분리
시각화 · 실제 코드명과 같은 연결도·실습 단계·보드 관찰값

03VS Code 실행 절차

00~12장 RTL을 VS Code에서 회귀 시험하고, 13~19장 정수 기준모델을 별도로 실행합니다. 실제 Vivado/Vitis·Basys3 실행은 각 해당 장의 절차와 검증 항목을 따릅니다.

Ubuntu Terminal · 공통 실행 순서
# 1. 공통 UART Echo
bash part03/ch00/scripts/run_sim.sh
# 2. DSP 4PE 독립 누적 경로
bash part03/mini_npu/scripts/run_engine.sh
# 3. UART RX→NPU→UART TX 전체 검사
bash part03/mini_npu/scripts/run_demo.sh
# 4. 독립 01~10장 포함 전체 회귀
bash part03/mini_npu/scripts/run_batch_00_12.sh
# 5. 13~19장 정수 연산 호스트 기준모델
python3 part03/host_tools/p3_integer_reference.py
# 6. UART FIFO·명령 경계 시험
bash part03/mini_npu/scripts/run_adversarial.sh

ch04 단독 실행기는 ripgrep(rg)을 사용합니다. 전체 회귀는 미설치 시 grep -E로 자동 대체합니다. 00~12장 로컬 RTL 실행 결과는 validation/P3_00_12_LOCAL_RTL_SIM_20261117_v01.md에 기록되어 있습니다.

04공통 소스 및 보드 연결

제3부 00~31장 전체 테크트리 · 통합 NPU 명령·모듈 설명 · Basys3 핀 제약

13~31장은 각 장의 목표·설계 규격·실습 코드·검증 절차로 구성합니다. 독립 정수 기준모델과 실제 RTL 시뮬레이션, 합성·타이밍, 실물 동작은 서로 구분해 진행합니다.
