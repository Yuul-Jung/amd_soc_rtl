제24장 · Basys3 자원·타이밍 분석

실제 Basys3 XC7A35T의 DSP·BRAM·LUT·FF 사용량과 WNS/TNS를 Vivado 보고서로 분석합니다.

Vivado QoR기능 분리검증 절차

00과제 개요

실제 Basys3 XC7A35T의 DSP·BRAM·LUT·FF 사용량과 WNS/TNS를 Vivado 보고서로 분석합니다.

선수학습: 21장 SoC 프로젝트·23장 성능 지표

산출물: Synthesis/Implementation 보고서·critical path·자원표

01시스템 구조

Verilog에 use_dsp/ram_style 속성이 있다는 사실만으로 실제 DSP48E1/BRAM 배치를 확정하지 않습니다.

02핵심 설계 계약

  • Basys3 타깃은 XC7A35T-1CPG236C, 실제 Part/Speed Grade를 프로젝트와 비교한다.
  • DSP/BRAM 추론 여부는 합성 Netlist/Report에서 판단한다.
  • WNS와 TNS는 Setup/Hold 및 Clock Constraint의 유효성에 따라 해석해야 한다.
  • Synthesis 시간 보고서와 Implementation/Route 타이밍은 다른 게이트다.

03따라 하기 실습

  1. 독립 SoC 신규 프로젝트와 part03/mini_npu/build 프로젝트 중 대상 하나를 선택한다.
  2. 100MHz 외부 클록과 모든 실제 핀 XDC 제약이 완전한지 검사한다.
  3. Synthesis를 실행하고 DSP48E1·RAMB18E1/RAMB36E1·LUT/FF 수를 수집한다.
  4. Implementation 후 Report Timing Summary에서 WNS/TNS와 Critical Path를 확인한다.
  5. 기능을 바꾸는 최적화가 필요하면 전후 RTL·TB·Timing 자료를 분리해 비교한다.

04코드·설정 예제

Vivado에서 합성 또는 구현 Run을 열어 놓은 상태에서 실행하는 보고서 명령이다. 이 코드는 실습용 예제이며 실제 Vivado·Vitis 빌드 성공과 구분합니다.

Vivado Tcl Report 명령 · tcl
# open_run synth_1 또는 open_run impl_1 이후에 실행
report_utilization -file utilization.rpt
report_timing_summary -file timing_summary.rpt
# Actual resource inference:
# report_utilization.hierarchical 정보도 비교
# WNS/TNS는 clock constraints와 함께 해석

05검증 항목

  • 패키지·핀·IOSTANDARD·클록 제약 및 미제약 경로가 없는지 확인.
  • 실제 DSP/BRAM 셀 사용과 코드 추론 기대를 대조.
  • WNS/TNS가 보고서에 존재하는 경우 Clock/Reset/CDC 별도로 점검.

호스트 계산, RTL Simulation, Synthesis·Timing, Basys3 실물 게이트의 증거를 서로 구분해 기록합니다.

06오류·확장 경계

  • 합성 PASS를 타이밍 수렴 PASS로 바꾸어 보고하지 않는다.
  • DSP 속성 지정만으로 실제 FPGA 배치를 확정하지 않는다.
  • 코드의 표현만 바꾼 경우를 타이밍 문제의 해결 코드라고 부르지 않는다.
