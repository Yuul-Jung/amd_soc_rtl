제31장 · AES-128·SHA-256/HMAC 모델 보호와 보안 UART

NPU 모델 전송에 AES-128 암호화와 HMAC-SHA-256 무결성·인증 검사를 더하는 보안 UART 종합 실습입니다.

종합 4 · 암호·인증종합 제작과제독립 검증

00과제 개요

NPU 모델 전송에 AES-128 암호화와 HMAC-SHA-256 무결성·인증 검사를 더하는 보안 UART 종합 실습입니다.

선수학습: 11장 UART X/W/B 프로토콜, 27장 NPU 시스템, NIST FIPS 197·HMAC

산출물: 인증 프레임 규격·호스트 암호화 테스트벡터·거부 정책·독립 FPGA 암호 가속기 검증 계획

01시스템 구조

SHA-256 해시는 인증이 아닙니다. HMAC-SHA-256은 별도 비밀키를 사용한 메시지 인증이며, AES-128은 메시지 기밀성을 제공합니다.

02핵심 설계 규칙

  • 암호 방식은 교육용 Encrypt-then-MAC(AES-CTR 암호화 후 HMAC-SHA-256 인증)으로 정의한다. MAC 확인 전에 복호·모델 반영을 하지 않는다.
  • AES-CTR의 Counter/Nonce는 같은 암호키에서 재사용하면 안 된다. 메시지 ID·Nonce·길이·Ciphertext 모두 MAC에 포함한다.
  • 암호화 키와 MAC 키는 분리하고 소스코드·Bitstream·공개 테스트 로그에 운영 키를 포함하지 않는다.
  • HMAC은 재전송 공격을 자동 방지하지 않으므로 Sequence/Replay 거부 및 저장 정책을 따로 설계한다.
  • Basys3는 보안 키 저장소나 Tamper 방어가 있다고 전제하지 않는다. 교육용 구현을 상용 보안 제품으로 주장하지 않는다.
  • AES-128 단독/ECB, SHA-256 Digest 단독을 인증·암호화를 모두 제공하는 솔루션으로 설명하지 않는다.

03따라 하기 실습

  1. FIPS 197 AES-128, NIST SP 800-38A CTR, HMAC-SHA-256의 각각 다른 역할을 비교한다.
  2. 프레임에 Version/Model ID/Sequence/Nonce/Length/Ciphertext/HMAC Tag를 배치한다.
  3. 호스트에서 인증과 암복호가 같은 키·고유 Nonce로 일치하는지 테스트한다.
  4. MAC 비트 변경, 길이 변조, Replay, 잘못된 키, 전원 도중 끊김에서 모델 Commit이 거부되는지 검사한다.
  5. 독립 AES-128·SHA-256/HMAC RTL을 구현한다면 NIST Known Answer Test를 통과시킨 뒤 UART NPU와 결합한다.
  6. 인증 완료 전까지 입력·가중치 Bank에 부분 반영하지 않도록 Staging→Atomic Commit 구조를 갖춘다.

04코드 및 처리 기준

다음은 운영 보안 구현이 아니라 호스트의 암호화·HMAC 규격 확인 예제이다. Python cryptography 패키지가 필요하다.

31장 Python 호스트 Encrypt-then-MAC 예제 · python
import secrets, hmac, hashlib
from cryptography.hazmat.primitives.ciphers import (
    Cipher, algorithms, modes,
)

enc_key = secrets.token_bytes(16)  # AES-128 교육용 난수 키
mac_key = secrets.token_bytes(32)  # 별도 HMAC 키
nonce = secrets.token_bytes(16)    # 동일 키에서 재사용 금지
data = b"MODEL-INT8-TEST"
header = b"P3-V1" + len(data).to_bytes(4, "big")

encryptor = Cipher(algorithms.AES(enc_key),
                   modes.CTR(nonce)).encryptor()
ciphertext = encryptor.update(data) + encryptor.finalize()
frame = header + nonce + ciphertext
tag = hmac.new(mac_key, frame, hashlib.sha256).digest()
assert hmac.compare_digest(
    tag, hmac.new(mac_key, frame, hashlib.sha256).digest()
)
print("authenticated=", len(tag) == 32)

authenticated= True

05동작 및 안전 검증

  • NIST AES-128 알려진 정답 벡터로 별도 암호 RTL을 검증한다.
  • HMAC-SHA-256은 단 한 비트 변조에도 거부되며 일정시간 비교 원칙을 검토한다.
  • Nonce/Sequence 중복, Replay, 손실/중단 프레임, 인증 실패 시 메모리에 모델을 Commit하지 않는다.
  • 키를 공개 HTML/RTL 파일/시뮬레이션 로그에 넣지 않는지 확인한다.
  • 독립 암호 모듈과 UART/NPU 결합 시 RTL Simulation 및 Timing/Resource를 따로 확인한다.

시뮬레이션·합성·실물 확인은 실제 실행 증거가 있는 경우에만 통과로 판정합니다.

06제약사항과 확장

  • HMAC은 SHA-256 해시값과 다르며 암호키 없이 단순 Digest만 전송하면 송신자 인증을 제공하지 않는다.
  • AES-CTR 자체는 무결성을 제공하지 않는다. 변조 대응을 위해 HMAC 인증이 반드시 필요하다.
  • Basys3는 비밀키 물리 보호·Secure Boot·Anti-Tamper를 제공한다고 전제하지 않는다.
  • 산업안전과 관련된 제어·안전 인증, 암호 구현의 실제 보안성은 교육 검증과 분리한다.
