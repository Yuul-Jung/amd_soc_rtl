0031장 전체를 4개 누적 프로젝트로 진행

각 장은 새 프로젝트를 다시 만드는 과정이 아니다. 이전 장의 코드와 배선·검증을 유지한 채 새로운 기능을 추가한다. 00~12장의 실제 UART 원형에서 출발해 10분류 NPU, MicroBlaze V SoC, 응용별 Controller로 발전한다.

실습 순서: 이전 산출물 확인 → 이번 기능 추가 → 자동 판정 RTL 시험 → Python 기준모델 대조 → 합성·구현 → 보드 입력·출력 확인 → 다음 장으로 인계.

02① UART 4분류 NPU — Basys3 실물 확인

소스 기준: mini_npu/rtl/basys3_npu_top.v / mini_npu/constraints/basys3_npu.xdc. 클록 100MHz, USB-UART 115200·8N1, BTNC Reset, LED0~3 클래스, FND 한 자리에 0~3.

  1. 정적·RTL 검증을 실행하여 실제 성공 로그와 소스 버전을 연결한다.
  2. 별도 Vivado 프로젝트에서 Synthesis를 완료한다. 기존 성공 프로젝트가 아닌 mini_npu/build/를 사용한다.
  3. Vivado에서 Open Project → Run Implementation → Generate Bitstream 순서로 빌드한다. DRC·WNS/TNS를 확인한다.
  4. Basys3 USB를 PC에 연결하고 Open Hardware Manager → Open Target → Auto Connect → Program Device로 실제 bitstream을 내려받는다.
  5. Ubuntu 시리얼 포트를 확인하고 115200·8N1, 흐름 제어 없음으로 접속한다.
  6. 문자 0, 1, 2, 3을 하나씩 전송하고 UART 응답의 클래스, LED0~3, FND 숫자를 서로 대조한다. LED14는 완료, LED15는 오류 래치 표시다.
  7. BTNC 리셋 전후 표시와 UART 재응답을 확인하고 보드 결과를 기록한다.
원본 RTL 재검증·합성·UART 포트 확인
# 00~12장 RTL 회귀 시험
bash part03/mini_npu/scripts/run_batch_00_12.sh
# FIFO·명령 경계 시험
bash part03/mini_npu/scripts/run_adversarial.sh
# 별도 Vivado 프로젝트 생성·합성 (Bitstream은 GUI에서 생성)
bash part03/mini_npu/scripts/run_vivado_synth.sh
# 실제 USB-UART 장치 포트 확인
ls -l /dev/serial/by-id/
# minicom 설치 후 사용: 실제 포트명으로 교체, 흐름 제어 비활성
minicom -D /dev/ttyUSB0 -b 115200 -8

터미널에서 입력하는 0~3은 이 4분류 예제 전용이다. X/W/B/R은 바이너리 페이로드를 사용하므로 문자 입력과 혼동하지 않는다.

03② 13~19장 — MNIST 10분류 누적·보드 확인

13장 입력 버퍼를 14장 4+4+2 스케줄과 연결하고 15~16장 Dense/MLP 계산을 완성한다. 17장에서는 784픽셀을 64×12+16으로 나누고 코어 외부에 부분합을 보존한다. 18장 INT8/16과 Float32는 같은 MNIST 시험 데이터로 비교한다.

  1. 00~12장 원본 RTL의 UART 및 기존 DSP 모듈을 참조하고, 10클래스 코어는 별도로 빌드한다. 4클래스 Top을 10클래스 구현으로 오해하지 않는다.
  2. 13~18장 RTL·TB를 순서대로 추가한다. 각 장의 중간 결과를 Python 정수 기준모델과 대조한다.
  3. 10클래스 UART 응답 또는 AXI 입력 프로토콜을 실제 새 Controller 코드에 맞춰 확정한다. 12장의 0~3 명령을 10클래스 명령이라고 가정하지 않는다.
  4. Vivado 합성·구현·Bitstream 이후, 0~9 테스트 이미지/특징 벡터를 동일 모델 버전으로 전송한다.
  5. 실제 UART 점수 10개, 분류 Class, FND 한 자리 숫자와 Python 결과를 기록한다. Reset·미적재 모델·오류 프레임도 확인한다.
  6. 19장에는 여러 PE 배치의 클록·자원·처리량을 같은 검증된 소스 기준으로 비교한다.
공통 Python 정수 기준모델 검증
# 13~19장 기준모델 자체 실행
python3 part03/host_tools/p3_integer_reference.py
# 8개 독립 단위 테스트
python3 -m unittest part03.host_tools.test_p3_integer_reference -v

보드 진행 조건: 10클래스 RTL·실제 Top·XDC·명령 프로토콜·TB를 먼저 확보한다. 현재 GitHub에는 해당 통합 코어 소스가 없어 이 실습의 보드 실행은 아직 수행할 수 없다.

04③ 20~27장 — MicroBlaze V + AXI NPU SoC 실습

  1. 20장: 독립 AXI4-Lite Slave RTL과 레지스터 표를 구성한다. AW/W 독립 수락, WSTRB, B/R backpressure 시험을 먼저 통과한다.
  2. 21장: 제1부 성공 Vivado 프로젝트를 File → Project → Save As로 새 폴더에 복제한다. 원본 프로젝트와 BD를 변경하지 않는다.
  3. 새 프로젝트에서 Tools → Create and Package New IP로 검증한 NPU IP를 패키징/등록한다. Block Design에서 MicroBlaze V·AXI·Clock/Reset과 실제 포트를 연결한다.
  4. Address Editor → Validate Design → Generate Output Products → Create HDL Wrapper를 진행한다. 관리형 Wrapper와 사용자 Top 연결을 구분한다.
  5. Run Synthesis → Run Implementation → Timing/DRC 확인 → Generate Bitstream을 진행하고 XSA(하드웨어 플랫폼 파일)를 내보낸다.
  6. 22장: Vitis Platform을 XSA에서 만든 후 C Application을 빌드한다. 실제 xparameters.h의 NPU 베이스 주소가 코드와 일치하는지 확인한다.
  7. CPU가 AXI 레지스터로 모델/입력 적재, START, DONE/ERROR, CLASS/Score를 읽는 절차를 구현한다. Basys3에 FPGA bitstream과 ELF를 내려받아 실제 UART·LED·FND 값을 비교한다.
  8. 23~25장은 동일 모델·동일 빌드 조건의 CPU/NPU 성능, 자원, 타이밍, 전력 보고서를 확보한다. 26장 CNN 경로는 27장 통합 시스템에서 기존 기능을 유지하며 확장한다.

AXI 주소·XSA·UART 결과·합성 자원은 예제가 아닌 실제 생성한 프로젝트 값을 사용한다. 각 도구의 PASS 여부를 별도 기록한다.

05④ 28~31장 — 공통 SoC 기준선에서 응용 분기

장기존 공통 기반실습 출력필수 확인
28 숫자27장 10분류 SoCPC 그림→클래스 0~9·UART·FND시험 입력 ID·Python/보드 결과 동일
29 센서27장 SoC·제2부 센서 입력NORMAL/WARNING/FAULT/UNKNOWN먼저 가상 센서 데이터; 3.3V 전기 호환 점검 후 실제 센서
30 모터29장 상태·검증된 PWM/모터 제어NPU 제안→승인 Controller→모터 드라이버모터 미연결 출력시험 → 별도 안전 인터록/전원 확인
31 보안 UART27장 SoC·11장 UART 기본 경로AES-CTR·HMAC 인증 결과호스트 인증 테스트→변조/재전송/Nonce→FPGA 구현 후에만 실물

네 응용은 모두 27장 공통 NPU를 이어받지만, 서로 다른 응용은 독립 분기로 관리한다. 안전 정지는 AI와 독립돼야 하며, 보안은 호스트 테스트 통과만으로 FPGA 인증 기능이 구현됐다고 볼 수 없다.
