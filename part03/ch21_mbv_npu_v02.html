제21장 · MicroBlaze V + NPU SoC 통합

제1부 MicroBlaze V 성공 프로젝트를 복제해 사용자 NPU IP와 Clock·Reset·AXI Interconnect를 연결합니다.

Block Design기능 분리검증 절차

00과제 개요

제1부 MicroBlaze V 성공 프로젝트를 복제해 사용자 NPU IP와 Clock·Reset·AXI Interconnect를 연결합니다.

선수학습: 20장 AXI IP, 제1부 11장 사용자 Top

산출물: 신규 독립 Vivado 프로젝트, BD 연결도, 실제 Address Map

01시스템 구조

기존 제1부 11장 성공 프로젝트는 수정하지 않습니다. 새 복제 프로젝트에서 NPU 제어/상태에만 AXI4-Lite를 사용합니다.

02핵심 설계 계약

  • CPU는 시작·상태·데이터 관리, NPU는 병렬 정수 연산에 집중한다.
  • 사용자 Top은 보드 핀, wire, BD Wrapper와 Controller 연결에만 사용하고 레지스터 연산을 넣지 않는다.
  • 동일 Clock Domain이 아닌 입력은 CDC/Reset 구조를 먼저 정한다.
  • MicroBlaze V 인터럽트·메모리 구성은 실제 2024.2 프로젝트 설정을 확인한 후 연결한다.
  • BD 생성 Wrapper, 독립 사용자 Top, Custom IP Wrapper는 용도가 서로 다르며 임의로 이름을 바꾸지 않는다.

03따라 하기 실습

  1. 검증된 제1부 11장 Vivado 프로젝트를 File → Project → Save As로 신규 경로에 복제한다.
  2. 20장의 Custom IP repository를 추가하고 IP Catalog에서 NPU 제어 IP를 인스턴스화한다.
  3. AXI Clock/Reset, S_AXI, IRQ(선택), Input/Output과 기존 AXI UART/GPIO를 연결한다.
  4. Address Editor에서 중복 없는 베이스 주소를 확인하고 Validate Design 후 새 HDL Wrapper를 생성한다.
  5. 새 프로젝트의 XSA를 별도로 Export하되 기존 제1부 XPR/BD는 보존한다.

04코드·설정 예제

Vivado Tcl Console에서 기존 설계의 실제 객체 목록을 확인하는 읽기 전용 절차이다. 이 코드는 실습용 예제이며 실제 Vivado·Vitis 빌드 성공과 구분합니다.

validate_bd_design

05검증 항목

  • Address Editor의 NPU 범위가 기존 UART/GPIO/BRAM과 겹치지 않는다.
  • Processor System Reset 및 CPU Clock Domain의 연결을 확인한다.
  • 새 Top에 기능 always/연산/선택 논리가 들어가지 않는다.
  • XSA와 Bitstream은 실제 Export/Generate가 완료된 경우에만 산출물로 기록한다.

호스트 계산, RTL Simulation, Synthesis·Timing, Basys3 실물 게이트의 증거를 서로 구분해 기록합니다.

06오류·확장 경계

  • 원본 성공 BD를 직접 개조하거나 소스 이름을 무조건 바꾸지 않는다.
  • UART로 모델 적재하는 기존 12장의 전송 정책과 AXI로 모델 적재하는 SoC 정책을 혼합하지 않는다.
  • 검증된 AXI4-Lite 사용자 IP만 실제 SoC로 연결한다.
