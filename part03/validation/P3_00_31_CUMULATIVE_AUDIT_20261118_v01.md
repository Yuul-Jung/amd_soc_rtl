## 1. 실제 확인된 문제

- 00~12장에는 독립 RTL·통합 RTL·TB가 있지만 13~31장은 대부분 HTML·Python 예제만 있으므로 31개 장을 별도 실습처럼 읽게 된다.
- 13~19장 10분류 모델과 20~27장 AXI SoC가 이전 코드·프로젝트와 누적되는 구조를 명확하게 연결하지 못했다.
- 20~27장에는 일부 GUI 개념 설명은 있으나 Vivado의 프로젝트 복제→IP→BD→Address Editor→Bitstream→XSA→Vitis→보드 확인 절차가 하나의 완결된 실습으로 연결되지 않았다.
- 28~31장도 27장 공통 SoC로부터 응용별 분기를 어디서 시작하는지, 실제 LED/FND/UART에서 확인할 값을 공통 양식으로 표시하지 못했다.

## 3. 정적 재검토

- 최신 GitHub 트리에서 32개 신규 HTML과 `course.json` 목록이 1:1 일치하고, 구버전 장 HTML은 남아 있지 않음.
- 32개 HTML 모두 `cumulative-lab`와 공통 실습 가이드 링크 포함.
- 32개 HTML + INDEX + 실습 안내서의 `href/src` 상대경로 존재 검증에서 누락 없음.
- 실습 안내서의 `board12`, `board10`, `soc`, `capstone` 앵커 존재 확인.
- 새 검사기를 GitHub에 등록했으나 **이 보고서 작성 환경에서 Python 검사기를 실행한 것은 아님**.
- 브라우저 표시/모바일/코드 복사 실제 기능은 별도 확인 필요.

## 4. 구현과 실제 보드 검증의 미완료 경계

- `P3_00_12_LOCAL_RTL_SIM_20261117_v01.md`에는 00~12 로컬 RTL 회귀 PASS 기록이 있다. 본 작업에서 해당 RTL을 재시뮬레이션한 것은 아니다.
- 13~31장 통합 RTL·Vivado BD·Vitis 실제 프로젝트는 현재 GitHub에 수록되지 않음. VS Code의 로컬 구현물과 Source SHA/로그 인계가 필요하다.
- 현 작업은 교재의 **누적 구성/따라하기 절차**를 완성한 것이며, FPGA Bitstream 생성·실물 동작·GitHub Pages 웹 실렌더 PASS가 아니다.
- 후속 13~31장 소스와 보드 증거가 확보되면 실제 파일 경로/신호/메뉴/예상 출력과 일치하도록 장별 절차를 다시 대조해야 한다.
