00과제 개요

1PE·4PE·8PE의 이론 연산량과 실제 메모리·타이밍 병목을 분리해 비교합니다.

선수학습: 14장 스케줄, 17장 타일, 18장 정밀도

산출물: MAC 수·PE 수·BRAM 대역폭·합성 결과 비교표

01구조와 데이터 흐름

PE 수가 늘어도 BRAM에서 피연산자를 동시에 공급하지 못하면 효율이 떨어집니다.

02핵심 설계 규격

  • 출력 10개×입력 64개의 총 MAC 수 640회는 PE 개수와 무관하다.
  • 발행 클록 수의 이론 하한과 실제 파이프라인/그룹 전환 지연을 구분한다.
  • BRAM 포트·가중치 복제·타이밍으로 발생하는 지연을 따로 합산한다.
  • 실제 DSP/BRAM/LUT/FF와 WNS/TNS는 Vivado 보고서를 확보한 뒤 기록한다.

03실습 절차

  1. 1·4·8PE에 대해 MAC 발행 클록의 이론 하한을 계산한다.
  2. 동기 BRAM의 1클록 읽기와 유효 데이터 정렬 비용을 추가한다.
  3. 가중치/입력 공급 포트 수에 따른 포화와 Stall 사례를 도식화한다.
  4. 같은 정밀도·같은 학습 모델로 결과값과 자원·타이밍을 비교한다.

04구현 및 확인 코드

독립 기준모델 또는 실습 코드이며, 실제 FPGA 배치·동작 검증과는 별개입니다.

19장 Python 발행 사이클 하한 · python
macs = 64*10
for pe in (1,4,8):
    cycles = (macs+pe-1)//pe
    print(pe, "PE:", cycles, "min-issue cycles")

예상 출력

1 PE: 640 min-issue cycles
4 PE: 160 min-issue cycles
8 PE: 80 min-issue cycles

05검증 및 실습 점검

  • 이론 숫자에 BRAM 접근·스톨·시작/완료 지연이 들어가지 않았음을 표시한다.
  • 동일한 전체 640MAC과 클래스 출력 계약을 유지한다.
  • Vivado Resource/Timing 결과를 대조하기 전 FPGA 성능 결론을 내지 않는다.

Python 호스트 정답, RTL 시뮬레이션, Vivado 합성·타이밍, 실물 관찰은 별도 검증으로 기록합니다.

06오류를 피하는 기준

  • 이론 하한을 보드 실측 속도라고 표기하지 않는다.
  • 8PE가 4PE의 정확히 두 배 속도라고 주장하지 않는다.
  • 정수 연산 증명과 실제 FPGA DSP 자원 배치 검증은 별도다.
