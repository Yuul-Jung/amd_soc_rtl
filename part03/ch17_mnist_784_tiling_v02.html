제17장 · 28×28 원본 픽셀의 분할 누산

MNIST 원본 784특징을 64개 이하의 13개 타일로 나눠 전체 내적을 계산합니다.

784 → 13타일단계형 실습PC 기준값 비교

00과제 개요

MNIST 원본 784특징을 64개 이하의 13개 타일로 나눠 전체 내적을 계산합니다.

선수학습: 16장 다층 MLP, 04장 동기 BRAM

산출물: 12×64+16 분할 규칙·Partial Sum 보존 계약

01구조와 데이터 흐름

784=64×12+16이므로 마지막 타일은 16개 원소만 유효합니다. 모든 타일의 부분 합을 더해야 원본 내적과 같습니다.

02핵심 설계 규격

  • 12장 64주소 X/W 메모리만으로 784개 전체 입력을 동시에 보관할 수 없다.
  • 타일 경계마다 누산기를 지우면 오답이므로 Clear는 전체 벡터 시작에서만 한다.
  • INT16×INT16 784개 항을 최악 범위에서 누산하면 signed40이 넘칠 수 있어 42비트 등 폭 재산정이 필요하다.
  • 10클래스와 여러 타일의 진행 상태, Last/Valid, 가중치 저장소를 별도로 설계한다.

03실습 절차

  1. 784개 입력을 64개씩 자르고 마지막 16원소 길이를 확인한다.
  2. 부분 누산의 합과 전체 정수 내적이 정확히 같음을 시험한다.
  3. 전체 모델에 적용할 때 10출력×13타일의 스케줄을 정한다.
  4. Overflow·Reset·중도 취소·타일 순서 교체를 회귀 테스트에 포함한다.

04구현 및 확인 코드

독립 기준모델 또는 실습 코드이며, 실제 FPGA 배치·동작 검증과는 별개입니다.

17장 Python 타일 내적 · python
from part03.host_tools.p3_integer_reference import (
    dot_signed, dot_tiled_64,
)
x = [i%7-3 for i in range(784)]
w = [i%5-2 for i in range(784)]
tiles = [x[i:i+64] for i in range(0,784,64)]
assert len(tiles) == 13 and len(tiles[-1]) == 16
assert dot_tiled_64(x,w) == dot_signed(x,w)
print("tiles=",len(tiles),"last=",len(tiles[-1]))

예상 출력

tiles= 13 last= 16

05검증 및 실습 점검

  • 784 전체 내적과 13타일 누산의 점수가 정확히 같다.
  • 마지막 16원소의 무효 48개 데이터를 누산하지 않는다.
  • RTL에서는 타일 경계와 누산기 완료 타이밍을 독립 검증한다.

Python 호스트 정답, RTL 시뮬레이션, Vivado 합성·타이밍, 실물 관찰은 별도 검증으로 기록합니다.

06오류를 피하는 기준

  • 8×8 다운샘플 실습을 28×28 원본 정답으로 대체하지 않는다.
  • INT16 784항은 기존 40비트 누산으로 무조건 안전하지 않다.
  • 타일링은 데이터 이동 구조가 추가돼야 하며 12장의 단순 파라미터 수정이 아니다.

07누적 RTL 실습 · 입력부터 Basys3 출력까지

① 이전 장에서 유지

14장 4PE 그룹·16장 Dense/MLP의 64원소 처리 단위

② 이번 장에 추가

784픽셀을 64×12+16으로 분할하고 각 타일마다 입력·가중치를 다시 채운다. 코어 누산기는 매 타일 초기화, 외부 signed 누산기에 부분합 합산.

③ 따라 하기·보드 확인

13타일 순서·마지막 16개·Busy/Done·중단/Reset 시험; dot_tiled_64와 동일. Bias는 전체 누산 후 1회, 784항 + 40비트 Bias의 전체 폭 재산정

④ 다음 장 인계

18장 Float/INT8/INT16 동일 784→10 모델 경로

13~19장 공통 NPU10 프로젝트 생성·입력 전송·보드 확인 절차. 10분류 RTL·Top·XDC가 실제 준비되기 전에는 12장 4분류 보드 이미지로 10분류 성공을 대신하지 않는다.
