00과제 개요

MicroBlaze V C 프로그램에서 모델·입력을 적재하고 START, BUSY, DONE, SCORE와 CLASS를 순서대로 다룹니다.

선수학습: 20장 Register Map, 21장 XSA·Vitis 플랫폼

산출물: MMIO 접근 드라이버·Timeout·에러 처리·10클래스 검증 절차

01시스템 구조

버스 레지스터 주소는 임의 상수가 아니라 21장의 실제 Address Editor와 BSP 헤더에서 확인해야 합니다.

02핵심 설계 계약

  • Xil_In32/Xil_Out32는 Register Map의 32비트 Access를 수행하며 비트마스크와 오프셋을 일치시킨다.
  • 모델 적재 완료 전에 START를 실행하지 않는다.
  • BUSY→DONE을 기다릴 때 무한 폴링 대신 Timeout을 적용한다.
  • 하위/상위 Score 읽기의 Snapshot 정책을 지키고 signed 폭 복원을 정의한다.
  • Vitis 2024.2의 실제 xparameters.h·SDT 생성값은 플랫폼에 따라 달라질 수 있다.

03따라 하기 실습

  1. 21장 XSA로 Vitis 2024.2 Platform과 Standalone Application을 만든다.
  2. 설계의 실제 NPU base address 매크로를 찾아 타입·주소 정렬을 확인한다.
  3. 입력/가중치/바이어스를 20장 레지스터 쓰기 순서에 따라 적재한다.
  4. START를 1회 발행한 뒤 DONE까지 Timeout 폴링한다.
  5. 결과 10개와 Argmax를 Python 정수 기준모델과 비교한다.

04코드·설정 예제

아래 코드는 주소 매크로를 실제 설계에서 연결해야 하는 핵심 드라이버 예제다. 이 코드는 실습용 예제이며 실제 Vivado·Vitis 빌드 성공과 구분합니다.

Vitis C — Register Access 골격 · c
#include <stdint.h>
#include "xil_io.h"

#ifndef NPU_BASE_ADDR
#error "Set NPU_BASE_ADDR to the actual xparameters.h address"
#endif

#define NPU_CTRL    0x00U
#define NPU_STATUS  0x04U
#define NPU_LENGTH  0x08U
#define NPU_CLASS   0x0CU
#define NPU_DONE    (1U << 1)

static int npu_wait_done(uint32_t timeout) {
    while (timeout-- != 0U) {
        uint32_t status = Xil_In32(NPU_BASE_ADDR + NPU_STATUS);
        if ((status & NPU_DONE) != 0U) return 0;
    }
    return -1;
}

/* 실제 적재 함수/헤더와 연결한 뒤 호출 */
static int npu_run(uint32_t length) {
    Xil_Out32(NPU_BASE_ADDR + NPU_LENGTH, length);
    Xil_Out32(NPU_BASE_ADDR + NPU_CTRL, 1U);
    return npu_wait_done(1000000U);
}

05검증 항목

  • 정상 완료·Timeout·Error·START while Busy를 구별한다.
  • 선언된 주소에 다른 IP가 배치되지 않았는지 실제 XSA를 확인한다.
  • UART 출력한 Score와 Python 정수 Score 10개를 비교한다.
  • 32비트 정렬·volatile MMIO API·메모리 순서를 확인한다.

호스트 계산, RTL Simulation, Synthesis·Timing, Basys3 실물 게이트의 증거를 서로 구분해 기록합니다.

06오류·확장 경계

  • 이 코드는 완성된 전체 Vitis 프로젝트가 아니며 실제 BSP 주소 매크로 정의가 필요하다.
  • 합성/실물 통과 전까지 보드 추론 성공이라고 보고하지 않는다.
  • 12장의 CPU 없는 UART 적재 프로토콜은 별도 데모로 유지한다.
