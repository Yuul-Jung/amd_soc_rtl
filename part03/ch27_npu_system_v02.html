BASYS3 · MicroBlaze V · 제3부 27/31

제27장 · 10클래스 NPU 시스템 종합 구성

4PE 기반 10분류·다층 MLP·AXI 제어·CPU 검증·상태표시를 하나의 재현 가능한 SoC 과제로 정리합니다.

핵심 통합기능 분리검증 절차

00과제 개요

4PE 기반 10분류·다층 MLP·AXI 제어·CPU 검증·상태표시를 하나의 재현 가능한 SoC 과제로 정리합니다.

선수학습: 13~26장 단계별 설계·성능·전력

산출물: 독립 프로젝트·검증 매트릭스·실제 이미지/정수 기준모델 연동

01시스템 구조

28~31장은 각기 다른 응용 종합과제입니다. 본 장은 공통 10클래스 NPU SoC 하드웨어 기준선 역할만 합니다.

02핵심 설계 계약

  • 원본 12장 4클래스 데모와 20장 이후 신규 10클래스 SoC를 분리한다.
  • Top에는 연결·wire·인스턴스만 두며 CPU 제어/표시 우선순위는 하위 모듈로 분리한다.
  • 데이터 입력 및 모델 적재는 AXI와 UART 중 실제 사용할 경로를 명시하고 단일 소유권을 준수한다.
  • 정답 비교는 Python Golden 10점수/클래스, AXI 레지스터, FPGA 결과를 같은 입력 ID로 연결한다.
  • SIM/Timing/Board 단계가 각각 PASS일 때만 해당 근거 파일을 통합 배포한다.

03따라 하기 실습

  1. 검증된 00~12장 원본 모듈을 기준으로 의존성·추가 10클래스 모듈 목록을 확인한다.
  2. 13~19장의 데이터 폭·분할 스케줄·스케일·Class10 계약을 하나로 고정한다.
  3. 20~22장의 AXI Register Bank·CPU driver·NPU Top을 독립 새 프로젝트에 통합한다.
  4. 23~25장의 정확도/Latency/Resource/Power를 동일 빌드 SHA에 연결한다.
  5. 기존 12장 기능에 회귀 오류가 없는지 비교한 뒤 28~31 응용에 공통 컴포넌트를 제공한다.

04코드·설정 예제

재현에 필요한 검증 상태 열을 통일하는 입력 템플릿이다. 이 코드는 실습용 예제이며 실제 Vivado·Vitis 빌드 성공과 구분합니다.

05검증 항목

  • 모델/가중치/입력의 SHA와 Vitis/Bitstream 빌드의 버전을 일치시킨다.
  • 보드의 실제 0~9 분류를 UART/LED/FND와 함께 확인한다.
  • 회귀 검증을 생략한 채 신규 기능 성공으로 선언하지 않는다.

호스트 계산, RTL Simulation, Synthesis·Timing, Basys3 실물 게이트의 증거를 서로 구분해 기록합니다.

06오류·확장 경계

  • 27장 시스템은 12장 프로젝트를 강제로 변경하는 누적 프로젝트가 아니다.
  • 31장 보안 또는 30장 모터 안전성을 이 장에서 이미 제공한 것으로 가정하지 않는다.
  • 제4부 전용 CDC 고급 최적화와 제5부 UVM 전문 검증은 여기에서 중복 구현하지 않는다.

07누적 실습 · MicroBlaze V 및 Basys3 확인

① 이전 장 소스·기준선

20~26장 검증된 AXI IP·BD·Vitis C 및 10분류 Core

② 이번 장에 추가

CPU → AXI Register → NPU → UART/LED/FND 전체 제어 경로를 독립 SoC 프로젝트에 고정

③ Vivado/Vitis·실물 절차

동일 MNIST 테스트 입력 → CPU START → NPU DONE → CLASS0~9/점수 UART → FND 자리 표시 → Reset·오류 재시험

④ 다음 장 인계

28~31장 개별 종합과제의 변경 금지 SoC 기준선

20~27장 공통 IP 등록·BD 연결·XSA/Vitis·Basys3 프로그램 순서. 실제 AXI IP, BD와 빌드 증거가 준비되기 전에는 구성 예제를 합성·보드 성공으로 간주하지 않는다.
