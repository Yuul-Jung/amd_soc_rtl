01. CPU·BRAM 구조를 한 장으로 보기

FPGA(에프피지에이, 재구성 가능한 디지털 회로 칩)는 “빈 작업장”이고, MicroBlaze V(마이크로블레이즈 브이, FPGA 안에 구성하는 소프트 CPU)는 “작업자”, BRAM(비램, 칩 내부 블록 메모리)은 “작업대에 놓인 설명서와 재료”라고 설명하면 이해가 쉽습니다. 다만 실제 하드웨어에서는 CPU와 메모리가 신호선·버스·컨트롤러로 연결됩니다.

그림 읽기 ① 왼쪽의 microblaze_riscv_0가 프로그램을 실행합니다.

그림 읽기 ② CPU가 다음 명령어를 가져올 때는 ILMB 경로를 사용합니다.

그림 읽기 ③ 변수를 읽거나 저장할 때는 DLMB 경로를 사용합니다.

그림 읽기 ④ 두 경로는 논리적으로 구분되지만, 이 실습에서는 공통 BRAM 자원에 연결됩니다.

즉석 질문: “명령어도 데이터도 BRAM에 있다면 왜 길이 두 개일까요?” → CPU의 명령어 접근과 데이터 접근을 구분하는 구조이기 때문입니다. 독립된 물리 메모리 두 개라는 뜻은 아닙니다.

02. 최소 SoC 구성 범위 — 문장별 풀이

학습안내서 핵심 문구교수자가 쉽게 풀어 말할 설명
MicroBlaze V를 FPGA 내부에 구성한다.“CPU 칩을 따로 꽂는 것이 아닙니다. FPGA 내부의 논리회로 자원으로 CPU 기능을 구현합니다.”
명령과 데이터를 저장할 BRAM을 붙인다.“CPU는 명령을 혼자 기억하지 못합니다. 프로그램과 변수를 놓을 기억장치가 필요합니다. 오늘은 FPGA 내부의 BRAM을 사용합니다.”
Clock/Reset 기본 블록을 확인한다.“CPU에는 동작 박자가 필요하고, 시작 상태를 정하는 리셋도 필요합니다. 오늘은 관련 IP가 만들어졌는지 살펴봅니다.”
Local Memory 16 KB와 BD 저장을 확인한다.“메모리 크기를 16 KiB로 지정하고, 회로도 파일을 저장하면 이번 장의 실습 목표에 도달합니다.”
GPIO·UART·Timer 등은 포함하지 않는다.“오늘은 주변장치가 아니라 CPU와 메모리만 이해합니다. LED 출력과 시리얼 통신은 다음 장들에서 차례로 붙입니다.”

SoC(에스오씨, 하나의 칩에 CPU·메모리·주변회로 등을 통합한 시스템)는 여러 부품을 따로 놓는 대신 한 칩 안의 시스템으로 구성하는 개념입니다. MicroBlaze V가 RISC-V(리스크-파이브, 개방형 명령어 집합 구조) 기반이라는 사실과, 현재 프로젝트에서 특정 ISA 확장 기능을 실제로 활성화했는지는 구분합니다. 설정 화면을 보지 않고 RV32IM 등의 사용 여부를 확정하지 않습니다.

03. Basys3 사양 — 숫자·핀의 뜻

원문 값쉬운 설명실습에서 의미
XC7A35T-1CPG236CBasys3에 들어 있는 FPGA 칩의 부품 모델명새 Vivado 프로젝트의 부품 선택 기준
100 MHz1초에 클록이 1억 번 반복되는 기준 신호클록 1주기는 10 ns
W5보드의 100 MHz 클록이 FPGA에 들어가는 핀외부 Clock 포트와 XDC에서 대응
U18가운데 버튼 BTNC가 연결되는 핀02장에서 외부 리셋 입력으로 연결
16 KiB16 × 1024 = 16,384 바이트01장 Local BRAM 초기 설정 크기
T = 1 / f  →  1 / 100,000,000 Hz  →  0.00000001 s  →  10 ns

쉽게 말하기: “클록은 CPU가 일하는 박자입니다. 100 MHz라는 말은 1초에 1억 번의 주기가 있다는 뜻입니다. 그 한 번이 10 ns입니다.”

혼동 방지: W5는 부품 핀 이름, 100 MHz는 신호 주파수, 10 ns는 주기입니다. 세 표현은 같은 종류의 값이 아닙니다. BRAM은 FPGA 내부 메모리이고, 보드의 SPI Flash는 FPGA 설정을 저장하는 장치이므로 역할이 다릅니다.

04. CPU 내부 — 5개 기능을 쉬운 말로

이름우리말 풀이직관적인 예
PC · Program Counter (프로그램 카운터)다음에 읽을 명령어의 주소를 가리킵니다.“교과서 몇 페이지를 읽을지 표시한 책갈피”
Instruction Fetch (인스트럭션 페치)PC 주소에서 명령어를 가져옵니다.책갈피를 보고 다음 지시문을 읽기
Instruction Decode (인스트럭션 디코드)가져온 명령이 무슨 일을 뜻하는지 해석합니다.지시문이 덧셈인지, 저장인지 이해하기
Register File (레지스터 파일)CPU 안에서 자주 쓰는 값을 잠깐 보관합니다.작업자의 손에 든 작은 메모지
ALU · Arithmetic Logic Unit (산술 논리 연산 장치)덧셈·비교·논리 연산 등을 수행합니다.간단한 계산기
Load/Store (로드/스토어)메모리에서 값을 읽고 메모리에 씁니다.창고에서 재료를 꺼내고 넣기

CPU가 하는 일을 순서로 말해 보기

① PC가 다음 주소를 가리킵니다. → ② 명령어를 가져옵니다. → ③ 명령어를 해석합니다. → ④ 레지스터·ALU·메모리를 사용해 일을 수행합니다. → ⑤ 다음 명령어로 진행합니다.

교수자 설명: 이 순서는 CPU를 이해하기 위한 단순화입니다. 파이프라인 단계 수, ISA 확장, 캐시 여부 같은 세부 구현 상태를 이 개념만으로 확정하지 않습니다.

05. ILMB·DLMB·BRAM — 경로별 해설

실제 표시 명칭교수자 해설
microblaze_riscv_0Vivado가 배치한 MicroBlaze V CPU의 인스턴스 이름입니다. CPU 종류와 이름을 구분합니다.
ILMB (Instruction Local Memory Bus)CPU가 명령어를 가져오기 위해 사용하는 로컬 메모리 접근 경로입니다.
DLMB (Data Local Memory Bus)CPU가 변수·스택 등의 데이터를 읽거나 쓰는 접근 경로입니다.
ilmb_v10, dlmb_v10각각 명령어·데이터 쪽 LMB 버스 연결에서 보이는 실제 IP/인터페이스 명칭입니다.
lmb_bram_if_cntlrCPU 쪽 LMB 요청과 BRAM 쪽 메모리 접근을 연결하는 인터페이스 컨트롤러입니다.
Block Memory GeneratorFPGA 내부 BRAM 자원을 메모리 블록으로 구성하는 IP입니다.

명령어를 가져올 때

PC → CPU의 명령어 접근 경로 → ILMB → LMB BRAM 인터페이스 컨트롤러 → BRAM의 명령어 읽기 → CPU

변수에 접근할 때

CPU의 Load/Store 요청 → DLMB → LMB BRAM 인터페이스 컨트롤러 → BRAM의 데이터 읽기·쓰기

주소의 뜻: 시작 주소가 0x00000000인 16 KiB 영역을 연속으로 배치하면 마지막 바이트 주소는 0x00003FFF입니다. 이는 0부터 16,383까지 총 16,384개 바이트 주소입니다. 실제 배치와 링크 영역 확인은 후속 장에서 진행합니다.

질문: “ILMB와 DLMB가 있다는 것은 반드시 RAM 칩이 두 개라는 말일까요?” → 아닙니다. 두 개의 논리적 접근 경로가 공통 메모리 자원으로 연결될 수 있습니다.

06. Vivado 프로젝트 생성 — 클릭마다 이유 설명

Vivado(비바도, FPGA 하드웨어 설계 프로그램) 2024.2 기준 절차입니다. 메뉴명은 실제 화면의 영문 표기를 유지합니다.

화면에서 할 일그때 해줄 설명확인
Quick Start → Create Project → Next“실습에서 쓸 하드웨어 설계 작업 공간을 새로 만듭니다. 기존 프로젝트를 덮어쓰는 기능이 아닙니다.”새 프로젝트 생성 대화상자
Project name: soc01_microblaze_bram“이번 실습 파일들을 묶는 프로젝트 이름입니다. 첫 번째 최소 SoC라는 의미가 담겨 있습니다.”철자 일치
Project location: ~/soc/hw“틸드(~)는 우분투 현재 사용자의 홈 폴더를 뜻합니다. 하드웨어 프로젝트를 hw 폴더에 저장합니다.”선택 폴더 확인
RTL Project / Do not specify sources at this time“나중에 회로 소스를 추가하겠습니다. 지금 소스 파일이 없는 것은 오류가 아닙니다.”선택 상태 확인
Parts → xc7a35tcpg236-1“설계 대상 칩을 정확하게 지정합니다. 다른 FPGA로 설정하면 자원과 핀이 달라질 수 있습니다.”부품 문자열 일치
Next → Finish“이제 빈 프로젝트가 준비되었습니다. 아직 회로나 프로그램이 실행된 것은 아닙니다.”Project Settings → General → Part
파일 이름 3개를 반드시 구분: soc01_microblaze_bram.xpr은 Vivado 프로젝트, soc01_mb_bram.bd는 블록 연결 설계도, *.v는 Verilog 소스 파일입니다. 이번 장은 .xpr과 .bd가 중심입니다.

화면 질문: “Sources가 비어 있는데 잘못된 것인가요?” → 아닙니다. 블록 설계를 아직 만들지 않았기 때문입니다.

07. Block Design 생성 — 이름과 역할

한 줄 조작쉬운 말
Flow Navigator → IP INTEGRATOR → Create Block Design“소스코드를 한 줄씩 쓰는 대신 기능 블록을 배치하고 연결하는 설계 화면을 엽니다.”
Design name → soc01_mb_bram“만들 설계도를 구분하는 이름을 지정합니다. 프로젝트 이름과 반드시 똑같을 필요는 없습니다.”
Directory → <Local to Project>“별도 위치가 아니라 현재 프로젝트 안에서 파일을 관리하도록 합니다.”
OK“빈 Diagram이 열립니다. 아직 CPU나 메모리가 배치되기 전이므로 비어 있는 것이 정상입니다.”
Sources → Design Sources → soc01_mb_bram.bd“블록 설계 파일이 만들어졌는지 실제 파일 목록에서 확인합니다.”

질문: “프로젝트를 만들었다고 CPU가 바로 생길까요?” → 아닙니다. 프로젝트는 작업 공간이고, CPU IP는 다음 단계에서 직접 추가해야 합니다.
