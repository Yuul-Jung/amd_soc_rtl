01. XDC 원문 — 핀 연결과 시간 제약을 읽는 순서

XDC(엑스디씨, FPGA 설계 제약 파일)는 물리 핀과 Clock 시간 정보를 Vivado에 알려 주는 문서입니다. 1교시에서 만든 외부 포트가 실제 XDC 이름과 일치하는지 확인합니다.

Basys-3-Master.xdc · 제02장 최종 적용 기준
## Clock signal
set_property -dict { PACKAGE_PIN W5 IOSTANDARD LVCMOS33 } [get_ports clk]
# (변경) 중복 Clock 객체 추가를 피하도록 -add 옵션 제거
create_clock -name sys_clk_pin -period 10.00 -waveform {0 5} [get_ports clk]

## Center Button : Reset
set_property -dict { PACKAGE_PIN U18 IOSTANDARD LVCMOS33 } [get_ports btnC]
코드 부분교수용 쉬운 풀이
## Clock signal“아래 내용이 클록에 대한 설정이라는 주석입니다. 앞의 #는 실행되지 않습니다.”
set_property“포트의 속성을 지정하는 Vivado Tcl 명령입니다.”
-dict“여러 개 속성을 묶어서 지정합니다.”
PACKAGE_PIN W5“외부 Clock 신호는 FPGA의 W5 핀에 연결합니다.”
IOSTANDARD LVCMOS33“3.3V LVCMOS 계열 입출력 규격을 사용합니다.”
[get_ports clk]“Top의 외부 포트 가운데 clk라는 이름의 신호를 선택합니다.”
create_clock“클록의 타이밍 제약을 만듭니다. 실제 발진기를 만드는 명령은 아닙니다.”
-name sys_clk_pin“클록 객체에 붙인 식별 이름입니다. 외부 포트 이름과 같을 필요는 없습니다.”
-period 10.00“한 주기 10 ns, 즉 100 MHz로 분석하도록 지정합니다.”
-waveform {0 5}“클록이 0 ns에 상승하고 5 ns에 하강하는 파형 기준을 지정합니다.”
PACKAGE_PIN U18“Reset에 사용할 가운데 버튼 입력은 FPGA의 U18 핀입니다.”
[get_ports btnC]“버튼 신호의 Top 외부 포트 이름이 btnC인지 선택하여 확인합니다.”
질문: “XDC에 W5를 썼는데 BD 외부 포트 이름이 clk_0인 상태에서도 그대로 적용될까요?” → 아닙니다. get_ports clk와 실제 Top 포트명이 일치해야 합니다.

02. create_clock의 -add 오류와 최종 수정 이유

원본 제02장 실습 기록에는 처음 create_clock -add를 사용했을 때 TIMING-6 Critical Warning이 발생한 과정이 남아 있습니다. 이번 설계에서는 Clock 제약을 없애지 않고, 불필요한 추가 옵션만 제거하여 해결했습니다.

XDC 상태원본 기록 결과판단
create_clock -addCritical Warning 2건, 일반 Warning 6건실습의 초기 오류 상태
Clock 제약 줄 전체를 주석 처리Critical Warning 0건, 일반 Warning 4건중간 비교 상태 · 최종 해법 아님
-add만 제거Critical Warning 0건, 일반 Warning 5건원본 프로젝트에서 확인된 최종 적용 방식

왜 제약을 아예 지우면 안 되나요? 타이밍 분석 기준으로 사용해야 하는 입력 클록 정보가 사라지거나 불충분해질 수 있기 때문입니다. -add가 모든 프로젝트에서 오류라는 뜻은 아닙니다. 현재 프로젝트의 중복 Clock 객체 문제를 확인하고 제거한 사례입니다.

한 줄 설명: “Clock은 제대로 100 MHz로 제약하면서, 같은 신호에 불필요한 제약을 추가하지 않도록 수정했습니다.”

03. Validate Design — 회로 연결의 첫 확인

① Diagram에서 Ctrl+S를 눌러 변경한 soc01_mb_bram.bd를 저장합니다.

② Diagram의 Validate Design 버튼을 클릭합니다. “연결과 속성의 일관성을 검사하는 단계입니다. 보드에 프로그램하는 기능은 아닙니다.”

③ Messages에서 Error와 Critical Warning, 일반 Warning을 나누어 확인합니다.

④ Clock Association을 확인합니다. CPU·Local Memory·Reset IP가 의도한 100 MHz 시스템 Clock과 연결되는지 봅니다.

⑤ interconnect_aresetn, peripheral_aresetn 등 AXI 측의 Active-Low Reset 신호를 확인합니다. 현재 AXI 주변장치 확장 전인 점을 구별합니다.

메시지/화면읽는 방법
Validation successful“Vivado가 현재 BD의 구조 검증을 통과시켰다는 뜻입니다. 보드 프로그램이 정상 실행됐다는 뜻이 아닙니다.”
미연결 IP 또는 Reset Error“발생한 포트의 시작·도착점, Reset 극성 및 Clock Domain을 확인합니다.”
BD 41-2670 등 미완성 AXI 주소 경고“아직 사용하지 않는 M_AXI_DP 경로인지, 실제 필요한 주변장치 누락인지 구분합니다. 경고를 무조건 무시하지 않습니다.”

판정 경계: Validate의 PASS는 BD 연결/설정 검증 범위입니다. 합성·타이밍·실물 동작을 동시에 증명하지 않습니다.

04. Output Products와 HDL Wrapper — 회로 파일의 계층

Block Design이 완성돼도 HDL 소스 파일처럼 합성 흐름에 통합하려면 출력 생성과 Wrapper 확인이 필요합니다.

작업실행 위치어떤 결과가 필요한가
① Generate Output Productssoc01_mb_bram.bd 우클릭합성·시뮬레이션용 출력 생성
② Output 관련 옵션 확인기존 Out of context per IP 설정IP 단위 출력 생성을 기존 프로젝트 설정에 맞춤
③ HDL Wrapper 생성없을 경우 BD 우클릭 → Create HDL WrapperLet Vivado tools manage wrapper and auto-update
④ Set as Top 확인Sources → Design Sourcessoc01_mb_bram_wrapper가 실제 Top으로 지정됐는지 확인

3개 파일의 관계

soc01_microblaze_bram.xpr → Vivado 프로젝트
soc01_mb_bram.bd → CPU·BRAM·Clock·Reset 연결도
soc01_mb_bram_wrapper.v → BD를 외부 입출력과 연결하는 HDL 바깥 껍데기

파일 생성과 Top 지정은 다릅니다. Wrapper 파일이 실제 폴더에 존재하더라도 Vivado Sources에서 Top 계층으로 지정되었는지 확인해야 합니다. .hwh, .hwdef 등 생성 산출물은 실행한 출력 생성 절차와 프로젝트 버전에 따라 로그·파일 존재 여부를 확인합니다.

질문: “Wrapper는 CPU 프로그램인가요?” → 아닙니다. HDL Wrapper는 하드웨어 블록을 밖과 연결하는 회로 계층입니다. C 실행 프로그램은 03장에서 작성합니다.

05. Synthesis → Implementation → Bitstream 진행

① Run Synthesis(런 신서시스, 회로 합성) — Vivado가 BD와 IP를 실제 FPGA 논리 자원으로 표현하도록 합성합니다. 결과 확인: 합성 완료 메시지와 오류, 자원 보고서.

② Run Implementation(런 임플리멘테이션, 배치·배선) — 합성한 논리를 FPGA 자원에 배치하고 신호 경로를 연결합니다. 결과 확인: impl_1 완료, 라우팅 실패 여부, 타이밍 요약.

③ Generate Bitstream(제너레이트 비트스트림, FPGA 설정 파일 생성) — 실제 FPGA에 내려보낼 설정 데이터를 만듭니다. 결과 확인: write_bitstream Complete! 또는 같은 의미의 완료 메시지.

④ 파일 확인 — *.runs/impl_1/ 아래에 해당 Top의 *.bit 파일이 생성됐는지 확인합니다. 예시의 Top은 soc01_mb_bram_wrapper입니다.

단계컴퓨터가 하는 일성공해도 아직 검증되지 않는 것
Synthesis논리회로로 변환배치·배선 및 동작
ImplementationFPGA 자원 배치·배선소프트웨어 실행과 실제 입출력
Generate BitstreamFPGA용 설정 파일 생성Basys3 실물 프로그램, C 실행 결과

원본 02장 구현 기록을 해석해 보기

원본 제02장 자료에는 write_bitstream Complete!, Routing Failed Routes 0, WNS +1.372 ns, TNS 0.000 ns, WHS +0.045 ns가 기록돼 있습니다. 이는 그때의 대상 프로젝트와 실행 조건의 결과입니다. 현재 수업에서 다시 빌드하면 자신의 Vivado 보고서로 확인해야 합니다.

WNS(Worst Negative Slack, 워스트 네거티브 슬랙)는 가장 나쁜 설정시간 여유를 나타냅니다. 양수라면 해당 보고서 범위에서 해당 설정시간 요구를 충족한 것입니다. 모든 경로가 올바르게 제약되었다거나 보드 전기적 문제가 없음을 자동으로 보장하지는 않습니다.

06. Warning 숫자만 보지 않고 종류별로 해석

원본 02장 최종 기록값쉬운 설명
Critical Warning0건“중요 경고가 0건으로 표시됐지만 일반 경고는 남아 있습니다.”
일반 Warning5건“남은 메시지의 종류와 대상 회로를 직접 읽어야 합니다.”
Setup WNS / TNS+1.372 ns / 0.000 ns“당시 보고서의 설정시간 여유 결과입니다.”
Hold WHS / THS+0.045 ns / 0.000 ns“당시 보고서의 유지시간 여유 결과입니다.”
Pulse Width WPWS+3.000 ns“당시 보고서의 펄스 폭 요구 관련 여유입니다.”
FPGA 자원LUT 1,731 · FF 1,441 · BRAM 4 · DSP 0“해당 구현 결과에서 사용한 논리·메모리·DSP 자원입니다.”
Power0.186 W“Vivado 도구의 추정치이며 실측 전력과 구분합니다.”

남은 경고 예: 원본의 LUTAR-1 2건은 Debug 경로의 비동기 Preset/Clear 관련, TIMING-9 1건은 CDC(시디씨, 클록 영역 교차) 관련, TIMING-18 1건은 비동기 버튼 Reset 입력 경로와 관련됩니다. 남은 경고 한 건의 상세 내용은 원본 자료만으로 확정하지 않습니다.

교수자 주의: “Critical Warning 0건이니 모든 문제가 해결됐습니다”라고 설명하지 않습니다. Timing Constraint 누락, CDC 및 일반 Warning은 각기 별도 분석이 필요할 수 있습니다.

07. 보고서 확인 명령을 한 줄씩 설명

다음은 Vivado Tcl Console에서 추가 점검할 수 있는 참고 명령입니다. 이번 교수용 자료에서 새로 실행하여 PASS를 확인한 명령은 아닙니다.

Vivado Tcl Console · Clock/Timing 진단
# 기준·생성 Clock 전체 목록과 주기
report_clocks
# 외부 clk 포트에 연결된 Clock 객체
get_clocks -of_objects [get_ports clk]
# 미제약·누락된 Timing 검사
check_timing -verbose
# 구현 방법론상 Warning 상세 확인
report_methodology
# Clock Domain Crossing 경로 확인
report_cdc
명령핵심 해설
report_clocks“Vivado가 현재 인식하고 있는 Clock이 무엇인지와 주기를 확인합니다.”
get_clocks -of_objects [get_ports clk]“clk 외부 포트에 연결되어 인식되는 Clock 객체가 무엇인지 찾습니다.”
check_timing -verbose“타이밍을 분석할 때 빠진 제약이나 문제를 상세히 점검합니다.”
report_methodology“설계 방법론 관련 경고와 권고를 출력합니다.”
report_cdc“서로 다른 Clock 영역 사이의 연결을 분석합니다. 설계가 단일 영역이라고 예상해도 실제 메시지를 확인합니다.”

하지 말아야 할 것: 원인을 분석하기 전에 set_false_path를 무작정 추가하여 경고만 사라지게 하지 않습니다.

09. 제02장 마무리·다음 제03장 연결

마지막 3분 판서

W5 → clk → clk_wiz_1 → CPU Clock
U18 → btnC → Reset Controller
locked → dcm_locked
mb_reset → CPU Reset

검증 단계를 한 문장씩

Validate → 회로 연결 확인
Synthesis → 논리 합성
Implementation → 배치·배선
Bitstream → FPGA 설정 데이터 생성
Vitis C 실행 → 아직 다음 장

질문핵심 정답
① 100 MHz는 몇 ns 주기인가?10 ns
② -add 제거 후 무엇을 유지했나?100 MHz Clock의 create_clock 제약
③ locked가 들어가는 Reset 입력은?dcm_locked
④ Bitstream 완료가 C 프로그램 실행을 뜻하나?아니요. 실제 소프트웨어 실행은 03장에서 확인
⑤ 일반 Warning이 남았다면?원인·경로·영향을 확인하고 무조건 PASS로 판단하지 않음

다음 장으로 연결하는 말: “CPU와 메모리를 연결하고 실제 FPGA에 설정할 Bitstream까지 만들었습니다. 이제 03장에서 XSA를 넘겨 Vitis로 C 프로그램을 컴파일하고 BRAM에 올려 CPU가 실제로 명령을 실행하도록 하겠습니다.”
