# 제1부 교수용 쉬운 해설서 — 제작·검증 기준

## 1. 목적
`amd_soc_rtl` 제1부 학습안내서를 기반으로 **교수가 수업에서 화면을 따라가며 한 줄씩 설명할 수 있는 별도 해설서**를 만든다. 원본 실습 안내서를 대체하거나 원본 성공 프로젝트를 변경하지 않는다.

- 학습안내서: 수행할 메뉴·값·코드·확인 결과
- 교수용 해설서: 같은 순서로 **무엇인지 → 왜 하는지 → 한 줄의 뜻 → 그때 화면에서 확인할 것 → 다음 장과 연결**
- 개념·구조·순서·시각화를 누적 적용한다.
- 교재 본문에는 검증 메모·제작 이력·AI 작업 코멘트를 포함하지 않는다. 검토 사항은 이 README와 별도 검증 기록에 둔다.

## 2. 기준 자료의 우선순위
1. 실물·빌드 등 실행 증거, AMD/Digilent 공식 사양
2. `rule_md/web/education-html/STANDARD.md` 및 `INTEGRATION.md` (고정 HTML 표준)
3. `rule_md/fpga-soc/MBV_SOC_rules.md`, `rule_md/common/code-style-rules.md`
4. `part01/legacy/pages/soc/` 아래 **제1부 01~10장 실제 학습안내서 HTML**
5. `part01/chapters/11_user_top_io_remap.html` (신편 제1부 11장)
6. `part01/legacy/docs/socNN.md`는 비교·참고 원고. HTML과 다르면 단순히 더 긴 내용을 합치지 않고 확인한다.

**중요한 기존 불일치:** `part01/legacy/docs/soc01.md`에는 01장에서 Clock/Reset 연결·Validate·Wrapper·합성/구현까지 포함하는 구형 순서가 남아 있으나, 현재 `part01/legacy/pages/soc/01_microblaze_bram_minimal_soc.html`은 01장을 CPU·16KiB BRAM·BD 저장으로 끝내고 실제 외부 연결·Validate를 02장으로 넘긴다. **교수용 01장은 현재 HTML의 장 경계를 따른다.** 구형 Markdown의 단계들을 01장 완료 조건에 다시 추가하지 않는다.

구 41장 교재의 `11_register_map_design_principles.html`과 신편 제1부 11장(P1-11)은 서로 다른 장이다.

## 3. 장별 반복 구성
1. 이번 장이 누적 시스템에서 차지하는 위치
2. 1분 구두 설명과 30분 개념·90분 실습의 교수 운영 예시
3. 실제 모듈/포트/신호명을 쓰는 박스형 하드웨어 구조도
4. 학습안내서 문장별 쉬운 풀이
5. Vivado/Vitis GUI 클릭 한 단계마다 **메뉴·입력값·이유·눈으로 볼 결과**
6. 명령·코드가 있는 장: **원본 코드 전문, 구문/한 줄 풀이, 실행 흐름, 주요 파라미터**
7. 실제 검증 가능한 범위와 아직 확인하지 않는 범위
8. 자주 받는 질문·오류 대처, 확인 질문과 다음 장 연결

07·08·09·10장의 보조 C 해설서(07_1, 08_1, 09_1, 10_1)도 필수 참고한다. C 설명은 헤더·AMD API·자료형·포인터·주소·비트 연산·함수 호출 순서를 원본 실제 소스에 맞춘다. RTL이 있는 장은 모듈·포트·클록·리셋·파라미터·FSM·AXI 동작과 코드/구조도를 일치시킨다.

## 4. 교수용 원고 검토 기준
- 원본의 프로젝트 이름, `.bd` 이름, IP 이름, 핀, 주소, 명령 문자열, 코드 구문과 충돌하지 않는가?
- 해당 장에서 실제로 생성·검증하는 결과와 후속 장의 과정을 혼합하지 않는가?
- 도식의 신호·모듈 이름이 실제 코드 또는 명시된 추상 개념과 일치하는가?
- 학습 중 예상 결과와 실제 실행 증거를 명확히 구분하는가?
- 공식 원본 도판은 변형하지 않고 원본 그림 + 독립 한글 풀이로 사용했는가?
- HTML 표준 배경/배너/좌측 목차/모바일/접근성/코드복사/버전 파일명을 따르는가?
- 정적 링크 검사와 실브라우저 렌더링·Vivado/Vitis·실물 검증의 상태를 분리 보고하는가?
