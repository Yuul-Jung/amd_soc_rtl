00. 수업 운영과 학습 연결

이번 장은 CPU가 FPGA 내부에 들어가고, CPU가 실행할 명령어와 데이터를 보관할 BRAM을 연결하는 실습입니다. 완료 지점은 Block Design 저장입니다. 외부 Clock/Reset 연결과 Validate Design은 02장에서 진행하고, 실제 C 프로그램 실행과 보드 동작은 후속 장에서 다룹니다.

수업을 여는 1분 설명

“컴퓨터가 일하려면 일을 처리하는 CPU와 실행할 명령을 담을 기억장치가 필요합니다. Basys3 FPGA에는 우리가 원하는 회로를 구성할 공간이 있습니다. 오늘은 그 안에 CPU와 작은 메모리를 놓고 서로 연결하겠습니다.”

앞뒤 장과 연결

01장: CPU·BRAM 기본 구조 및 BD 저장 → 02장: Clock/Reset·외부 핀·검증 → 03장: BRAM 프로그램 실행 → 04~05장: 주소·AXI → 06~10장: 주변장치·통합 → 11장: 사용자 Top.

수업 시간 예시설명·활동확인 항목
0~30분CPU·FPGA·BRAM·ILMB/DLMB·10ns 원리와 구조도CPU와 메모리 역할을 말로 구분
30~60분Vivado 프로젝트 생성과 Block Designsoc01_microblaze_bram.xpr / soc01_mb_bram.bd
60~95분MicroBlaze V 추가, Block Automation 설정, 계층 펼치기microblaze_riscv_0, Local Memory 16KB
95~120분Clock/Reset 기본 블록·XDC 해설·저장·질문필요 IP 생성과 BD 저장; 아직 FPGA 실행 아님

교수자 강조: 첫 장부터 LED 점등을 성공 기준으로 요구하지 않습니다. 01장의 핵심 결과물은 하드웨어를 설계한 파일과 내부 블록 연결입니다.

01. CPU·BRAM 구조를 한 장으로 보기

FPGA(에프피지에이, 재구성 가능한 디지털 회로 칩)는 “빈 작업장”이고, MicroBlaze V(마이크로블레이즈 브이, FPGA 안에 구성하는 소프트 CPU)는 “작업자”, BRAM(비램, 칩 내부 블록 메모리)은 “작업대에 놓인 설명서와 재료”라고 설명하면 이해가 쉽습니다. 다만 실제 하드웨어에서는 CPU와 메모리가 신호선·버스·컨트롤러로 연결됩니다.

그림 읽기 ① 왼쪽의 microblaze_riscv_0가 프로그램을 실행합니다.

그림 읽기 ② CPU가 다음 명령어를 가져올 때는 ILMB 경로를 사용합니다.

그림 읽기 ③ 변수를 읽거나 저장할 때는 DLMB 경로를 사용합니다.

그림 읽기 ④ 두 경로는 논리적으로 구분되지만, 이 실습에서는 공통 BRAM 자원에 연결됩니다.

즉석 질문: “명령어도 데이터도 BRAM에 있다면 왜 길이 두 개일까요?” → CPU의 명령어 접근과 데이터 접근을 구분하는 구조이기 때문입니다. 독립된 물리 메모리 두 개라는 뜻은 아닙니다.

02. 최소 SoC 구성 범위 — 문장별 풀이

학습안내서 핵심 문구교수자가 쉽게 풀어 말할 설명
MicroBlaze V를 FPGA 내부에 구성한다.“CPU 칩을 따로 꽂는 것이 아닙니다. FPGA 내부의 논리회로 자원으로 CPU 기능을 구현합니다.”
명령과 데이터를 저장할 BRAM을 붙인다.“CPU는 명령을 혼자 기억하지 못합니다. 프로그램과 변수를 놓을 기억장치가 필요합니다. 오늘은 FPGA 내부의 BRAM을 사용합니다.”
Clock/Reset 기본 블록을 확인한다.“CPU에는 동작 박자가 필요하고, 시작 상태를 정하는 리셋도 필요합니다. 오늘은 관련 IP가 만들어졌는지 살펴봅니다.”
Local Memory 16 KB와 BD 저장을 확인한다.“메모리 크기를 16 KiB로 지정하고, 회로도 파일을 저장하면 이번 장의 실습 목표에 도달합니다.”
GPIO·UART·Timer 등은 포함하지 않는다.“오늘은 주변장치가 아니라 CPU와 메모리만 이해합니다. LED 출력과 시리얼 통신은 다음 장들에서 차례로 붙입니다.”

SoC(에스오씨, 하나의 칩에 CPU·메모리·주변회로 등을 통합한 시스템)는 여러 부품을 따로 놓는 대신 한 칩 안의 시스템으로 구성하는 개념입니다. MicroBlaze V가 RISC-V(리스크-파이브, 개방형 명령어 집합 구조) 기반이라는 사실과, 현재 프로젝트에서 특정 ISA 확장 기능을 실제로 활성화했는지는 구분합니다. 설정 화면을 보지 않고 RV32IM 등의 사용 여부를 확정하지 않습니다.

03. Basys3 사양 — 숫자·핀의 뜻

원문 값쉬운 설명실습에서 의미
XC7A35T-1CPG236CBasys3에 들어 있는 FPGA 칩의 부품 모델명새 Vivado 프로젝트의 부품 선택 기준
100 MHz1초에 클록이 1억 번 반복되는 기준 신호클록 1주기는 10 ns
W5보드의 100 MHz 클록이 FPGA에 들어가는 핀외부 Clock 포트와 XDC에서 대응
U18가운데 버튼 BTNC가 연결되는 핀02장에서 외부 리셋 입력으로 연결
16 KiB16 × 1024 = 16,384 바이트01장 Local BRAM 초기 설정 크기
T = 1 / f  →  1 / 100,000,000 Hz  →  0.00000001 s  →  10 ns

쉽게 말하기: “클록은 CPU가 일하는 박자입니다. 100 MHz라는 말은 1초에 1억 번의 주기가 있다는 뜻입니다. 그 한 번이 10 ns입니다.”

혼동 방지: W5는 부품 핀 이름, 100 MHz는 신호 주파수, 10 ns는 주기입니다. 세 표현은 같은 종류의 값이 아닙니다. BRAM은 FPGA 내부 메모리이고, 보드의 SPI Flash는 FPGA 설정을 저장하는 장치이므로 역할이 다릅니다.

04. CPU 내부 — 5개 기능을 쉬운 말로

이름우리말 풀이직관적인 예
PC · Program Counter (프로그램 카운터)다음에 읽을 명령어의 주소를 가리킵니다.“교과서 몇 페이지를 읽을지 표시한 책갈피”
Instruction Fetch (인스트럭션 페치)PC 주소에서 명령어를 가져옵니다.책갈피를 보고 다음 지시문을 읽기
Instruction Decode (인스트럭션 디코드)가져온 명령이 무슨 일을 뜻하는지 해석합니다.지시문이 덧셈인지, 저장인지 이해하기
Register File (레지스터 파일)CPU 안에서 자주 쓰는 값을 잠깐 보관합니다.작업자의 손에 든 작은 메모지
ALU · Arithmetic Logic Unit (산술 논리 연산 장치)덧셈·비교·논리 연산 등을 수행합니다.간단한 계산기
Load/Store (로드/스토어)메모리에서 값을 읽고 메모리에 씁니다.창고에서 재료를 꺼내고 넣기

CPU가 하는 일을 순서로 말해 보기

① PC가 다음 주소를 가리킵니다. → ② 명령어를 가져옵니다. → ③ 명령어를 해석합니다. → ④ 레지스터·ALU·메모리를 사용해 일을 수행합니다. → ⑤ 다음 명령어로 진행합니다.

교수자 설명: 이 순서는 CPU를 이해하기 위한 단순화입니다. 파이프라인 단계 수, ISA 확장, 캐시 여부 같은 세부 구현 상태를 이 개념만으로 확정하지 않습니다.

05. ILMB·DLMB·BRAM — 경로별 해설

실제 표시 명칭교수자 해설
microblaze_riscv_0Vivado가 배치한 MicroBlaze V CPU의 인스턴스 이름입니다. CPU 종류와 이름을 구분합니다.
ILMB (Instruction Local Memory Bus)CPU가 명령어를 가져오기 위해 사용하는 로컬 메모리 접근 경로입니다.
DLMB (Data Local Memory Bus)CPU가 변수·스택 등의 데이터를 읽거나 쓰는 접근 경로입니다.
ilmb_v10, dlmb_v10각각 명령어·데이터 쪽 LMB 버스 연결에서 보이는 실제 IP/인터페이스 명칭입니다.
lmb_bram_if_cntlrCPU 쪽 LMB 요청과 BRAM 쪽 메모리 접근을 연결하는 인터페이스 컨트롤러입니다.
Block Memory GeneratorFPGA 내부 BRAM 자원을 메모리 블록으로 구성하는 IP입니다.

명령어를 가져올 때

PC → CPU의 명령어 접근 경로 → ILMB → LMB BRAM 인터페이스 컨트롤러 → BRAM의 명령어 읽기 → CPU

변수에 접근할 때

CPU의 Load/Store 요청 → DLMB → LMB BRAM 인터페이스 컨트롤러 → BRAM의 데이터 읽기·쓰기

주소의 뜻: 시작 주소가 0x00000000인 16 KiB 영역을 연속으로 배치하면 마지막 바이트 주소는 0x00003FFF입니다. 이는 0부터 16,383까지 총 16,384개 바이트 주소입니다. 실제 배치와 링크 영역 확인은 후속 장에서 진행합니다.

질문: “ILMB와 DLMB가 있다는 것은 반드시 RAM 칩이 두 개라는 말일까요?” → 아닙니다. 두 개의 논리적 접근 경로가 공통 메모리 자원으로 연결될 수 있습니다.

08. MicroBlaze V IP 추가 — 무엇이 생기나

IP(Intellectual Property, 아이피, 재사용 가능한 설계 기능 블록)는 Vivado가 제공하는 CPU·메모리·통신 같은 회로 구성요소입니다.

① Diagram의 + (Add IP)를 누릅니다. “회로 기능 블록을 추가하는 도구입니다.”

② MicroBlaze V 검색 후 해당 IP를 더블클릭합니다. “예전 MicroBlaze와 MicroBlaze V는 구별해야 합니다. 이번 실습은 RISC-V 기반 MicroBlaze V입니다.”

③ microblaze_riscv_0 확인 “첫 번째 CPU 블록이란 뜻의 인스턴스 이름이 만들어졌습니다. 실제 이름이 다르면 화면의 이름을 기준으로 합니다.”

④ Run Block Automation 표시 확인 “CPU만 배치했으므로 기본 메모리·클록·리셋·디버그 계층을 더 구성해야 합니다.”

M_AXI_DP는 후속 AXI 주변장치 연결에 사용하는 인터페이스입니다. 01장에서 GPIO나 UART를 추가하지 않는다는 것은 기능 누락이 아니라 의도한 학습 범위입니다.

09. Run Block Automation — 설정 한 항목씩

Run Block Automation(런 블록 오토메이션, 블록 자동 구성)은 CPU 주변의 최소 구성 회로를 자동 생성·연결하는 기능입니다. 각 항목의 이유까지 설명하고 나서 OK를 누릅니다.

설정 항목학습안내서 값풀어서 설명할 문장
PresetNone“특정 고성능 프리셋 대신 필요한 기본 요소를 확인하겠습니다.”
Local Memory16 KB“명령어와 변수를 저장할 기본 메모리 공간을 16 KiB로 지정합니다.”
Local Memory ECCNone“오류 정정 회로는 지금 단계에서 제외하고, 기본 메모리부터 이해합니다.”
Cache ConfigurationNone“캐시는 빠른 임시 메모리 계층입니다. 첫 장에서는 경로를 단순하게 유지하기 위해 사용하지 않습니다.”
Debug ModuleDebug Enabled“나중에 Vitis에서 CPU를 멈추거나 실행 상태를 살펴볼 수 있도록 디버그 기능을 둡니다.”
Peripheral AXI PortEnabled“후속 장에서 GPIO·UART 등을 연결할 수 있도록 통로를 마련합니다. 아직 주변장치를 연결하지는 않습니다.”
Interrupt ControllerOff“인터럽트는 주변장치가 CPU에 즉각 처리할 일을 알리는 기능입니다. 09장에서 집중적으로 학습합니다.”
Clock ConnectionNew Clocking Wizard“CPU 동작 박자를 공급할 클록 생성 IP를 만들되, 보드 외부 핀까지의 최종 연결은 02장에서 합니다.”

교수자 주의: AMD 문서의 공식 설정 그림은 참고 도판입니다. 특정 GUI 버전의 모든 버튼·체크값이 실제 실습 환경과 일치한다고 추정하지 않습니다. 실행 화면에서 보이는 항목과 값으로 확인합니다.

10. 자동 생성된 IP — 어느 블록을 볼까

블록·신호교수용 한 줄 설명확인 포인트
microblaze_riscv_0“프로그램을 실행하는 CPU 본체입니다.”CPU IP 존재
microblaze_riscv_0_local_memory 등“CPU 가까이의 명령어·데이터 메모리를 묶은 계층입니다.”계층 확장해 ILMB/DLMB·BRAM 보기
clk_wiz_* · clk_out1“Clocking Wizard가 출력하는 시스템 클록을 뜻합니다.”클록 IP 생성
proc_sys_reset / rst_clk_wiz_*“CPU와 버스를 정해진 순서로 초기화하는 회로입니다.”리셋 IP 생성

계층을 펼치는 순서

① Diagram에서 microblaze_riscv_0_local_memory와 비슷한 이름의 계층을 찾습니다. → ② 계층 내부를 열어 ILMB Controller와 DLMB Controller를 확인합니다. → ③ 두 경로가 Block Memory Generator 쪽으로 연결되는지 따라갑니다.

정확한 표현: clk_wiz_*처럼 별표가 붙은 표기는 실제 블록 이름이 아니라 여러 생성 이름을 대표한 표현입니다. 실제 화면의 정확한 인스턴스 이름을 읽어서 설명합니다.

11. Clock과 Reset — 왜 둘 다 필요한가

개념쉽게 설명하기01장/02장 구분
Clock(클록, 동작 박자)“회로가 언제 값을 받아들이고 다음 상태로 바뀌는지 기준을 주는 신호입니다.”01장: 관련 IP 존재 / 02장: 외부 100 MHz와 연결
Reset(리셋, 초기화)“전원을 켜거나 버튼을 눌렀을 때 회로를 정해진 시작 상태로 돌려놓습니다.”01장: 관련 IP 존재 / 02장: 외부 버튼·극성·연결 확인
locked“클록 생성 회로의 출력이 안정된 상태인지 알리는 신호입니다.”02장 리셋 연결을 검토할 때 필요
dcm_locked“Processor System Reset이 클록 안정 상태를 전달받는 입력입니다.”02장 실제 연결 확인

질문: “CPU에 전원만 공급하면 순서대로 동작할까요?” → 아닙니다. 정상적인 동작을 위해 클록, 리셋, 필요한 메모리 연결이 함께 갖추어져야 합니다.

범위 확인: 오늘은 IP가 자동 생성되었는지만 봅니다. 외부 포트를 생성하거나 Reset 극성을 수정하고 Validate Design을 실행하는 행위는 02장의 절차입니다.

12. XDC — 실제 명령 한 줄씩 읽기

XDC(Xilinx Design Constraints, 자일링스 설계 제약 파일)는 “설계의 어떤 신호가 실제 칩의 어느 핀에 연결되는지, 클록 시간 기준은 무엇인지” Vivado에 알려 줍니다. 이 장에서는 파일을 등록하고 내용을 읽습니다. 실제 외부 포트와의 정합성 검증은 02장에서 합니다.

Basys3 Clock·BTNC Reset 기준 XDC
## Clock signal
set_property -dict { PACKAGE_PIN W5 IOSTANDARD LVCMOS33 } [get_ports clk]
create_clock -name sys_clk_pin -period 10.00 -waveform {0 5} [get_ports clk]

## Center Button : Reset
set_property -dict { PACKAGE_PIN U18 IOSTANDARD LVCMOS33 } [get_ports btnC]
원본 코드 한 줄교수자가 읽어 줄 쉬운 뜻
## Clock signal“아래 명령이 클록 신호와 관련된다는 주석입니다. ## 뒤 문장은 사람이 읽는 설명이고 설정 명령은 아닙니다.”
set_property“선택한 대상에 속성을 지정하라는 Vivado 명령입니다.”
-dict { ... }“여러 속성을 한꺼번에 지정할 때 쓰는 형식입니다.”
PACKAGE_PIN W5“클록 입력 clk를 FPGA의 W5 핀에 연결하도록 지정합니다.”
IOSTANDARD LVCMOS33“이 포트에 3.3 V 계열 LVCMOS I/O 전기 규격을 적용합니다.”
[get_ports clk]“설계의 최상위 외부 포트 중 clk라는 이름의 포트를 찾습니다. 포트가 없거나 이름이 다르면 의도대로 적용되지 않습니다.”
create_clock“클록의 시간 정보를 Vivado 타이밍 분석에 알려 줍니다. 실제 클록 회로를 새로 만든다는 뜻은 아닙니다.”
-name sys_clk_pin“이 타이밍 제약 클록의 이름을 붙입니다.”
-period 10.00“한 주기를 10.00 ns로 설정합니다. 100 MHz의 주기와 일치합니다.”
-waveform {0 5}“주기 안에서 상승 시점은 0 ns, 하강 시점은 5 ns로 설명합니다. 50% 듀티의 예입니다.”
## Center Button : Reset“아래 설정이 보드의 가운데 버튼 리셋 입력과 관계됨을 설명하는 주석입니다.”
PACKAGE_PIN U18“보드 가운데 버튼이 연결된 FPGA U18 핀을 지정합니다.”
[get_ports btnC]“설계의 최상위 외부 포트 이름이 btnC일 때 그 포트를 선택합니다.”

반드시 짚을 차이

set_property는 핀과 전기 규격을 지정합니다. create_clock는 타이밍 분석을 위한 주기 정보를 지정합니다. 두 명령을 섞어 이해하지 않도록 설명합니다. clk, btnC는 포트 이름이므로 실제 설계와 일치해야 합니다.

교수자 메모: 원본 HTML에는 이 프로젝트 기준의 -add 없는 create_clock이 제시되어 있습니다. 다른 단계의 구버전 Markdown 문장을 그대로 복사하여 -add를 다시 붙이지 않습니다.

14. 자주 받는 질문·오류 대응

질문·현상즉시 설명하고 확인할 것
“MicroBlaze V가 검색되지 않아요.”“설치된 Vivado 버전·IP 카탈로그와 프로젝트 부품을 확인합니다. 구형 MicroBlaze를 대신 추가하지 않습니다.”
“Run Block Automation이 안 보여요.”“현재 활성 Diagram과 CPU IP 종류, Designer Assistance 표시를 확인합니다.”
“BRAM이 안 보여요.”“Local Memory가 계층 블록 안에 접혀 있을 수 있습니다. 해당 계층을 먼저 펼칩니다.”
“16 KB는 메모리 하나인가요?”“이번 구성에서 설정한 Local Memory의 크기입니다. 물리 BRAM 프리미티브가 정확히 1개라는 의미로 읽지 않습니다.”
“W5와 U18 중 어느 쪽이 Clock인가요?”“W5는 100 MHz 입력, U18은 가운데 버튼 입력입니다.”
“clk_0인데 XDC는 clk예요.”“이름이 다른 상태입니다. 02장에서 실제 외부 포트를 정리하고 XDC 참조 이름과 맞춰야 합니다.”
“Validate를 누르니 오류가 생겼어요.”“01장 완료 조건에는 Validate가 없습니다. 외부 Clock/Reset 연결 이후 02장에서 검증합니다.”
“보드의 LED가 안 켜져요.”“정상일 수 있습니다. 아직 LED 출력을 위한 GPIO와 실행 프로그램을 구성하지 않았습니다.”
“BRAM과 Flash는 같은가요?”“아닙니다. BRAM은 FPGA 내부의 동작용 메모리이고, 보드 SPI Flash는 주로 FPGA 구성 데이터 저장에 사용됩니다.”

15. 수업 마무리 — 판서·질문·다음 장

마지막 3분 판서

CPU는 명령어를 실행한다.
BRAM은 명령어와 데이터를 담는다.
ILMB는 명령어 접근, DLMB는 데이터 접근이다.
Clock은 동작 박자, Reset은 초기화다.
.xpr은 프로젝트, .bd는 블록 설계도다.

다음 장으로 넘길 말

“CPU와 메모리를 블록 설계에 배치했습니다. 하지만 실제 Basys3 보드의 클록 핀과 리셋 버튼을 제대로 연결하고 검증해야 동작 가능한 시스템이 됩니다. 그 작업을 02장에서 이어서 하겠습니다.”

확인 질문핵심 답변
① CPU는 어디에 만들어지는가?Basys3 FPGA 내부의 구성 가능한 논리회로 자원
② ILMB와 DLMB는 무엇이 다른가?각각 명령어 접근과 데이터 접근 경로
③ 100 MHz의 주기는 얼마인가?10 ns
④ create_clock은 물리 클록을 새로 생성하나?아니요. Vivado 타이밍 분석용 클록 제약을 기술한다.
⑤ 01장 완료 후 보드 LED가 켜져야 하나?아니요. 01장은 BD 저장 단계이고 주변장치·프로그램 실행 전이다.
